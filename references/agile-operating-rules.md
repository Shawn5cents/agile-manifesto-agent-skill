# Agile operating rules

## Four-value translation

Use this practical translation:

| Agile value | Practical behavior |
|---|---|
| People and collaboration | Resolve ambiguity through direct conversation and shared understanding. |
| Working software | Make the thing run; show evidence instead of just describing it. |
| Customer collaboration | Validate with the person who uses or pays for the result. |
| Responding to change | Re-plan when new evidence makes the old plan wrong. |

## Twelve-principle translation

Apply these as operating checks:

1. Deliver useful value early and repeatedly.
2. Welcome changed requirements when they improve the outcome.
3. Ship working increments frequently.
4. Keep business/customer context close to builders.
5. Build around motivated people and give them support.
6. Prefer direct communication for complex ambiguity.
7. Measure progress through working results.
8. Maintain a sustainable pace.
9. Use technical excellence and good design to keep speed possible.
10. Simplify by cutting work that does not need to exist.
11. Let strong teams organize around the goal.
12. Reflect regularly and adjust behavior based on evidence.

## Anti-pattern checklist

Flag these when they appear:

- Big plan with no shippable slice.
- Tooling debate that avoids customer value.
- Documentation used to hide missing implementation.
- Architecture work with no demo path.
- No user/customer feedback loop.
- No test, log, screenshot, artifact, or deployment proving progress.
- Endless refactor before first usable result.
- Process ceremonies added without solving a real coordination problem.

## Recommended response tone

Be direct, practical, and implementation-focused. Use Agile language only when it clarifies decisions. Avoid corporate Agile jargon unless the user asks for Scrum, Kanban, sprint planning, user stories, or formal agile coaching.

## Common transforms

Turn "build the whole thing" into: first vertical slice.
Turn "write a huge spec" into: short goal, constraints, first testable increment.
Turn "which framework" into: fastest path to working evidence.
Turn "we are stuck" into: remove blockers to a demo.
Turn "is this agile" into: compare it against delivery, feedback, adaptation, simplicity, and sustainability.
